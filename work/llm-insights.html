Narrative layer on a metrics model

Case note wrapping the live Insights demo. A short ops note in, a briefing out, from the same sample snapshots. An LLM can sit on that contract later. No API key on the public page.

Situation

A dashboard answers “what is the number.” Standups still spend time turning that number into five sentences. That last step is a function over a metrics model, not a new report.

Constraint

Do not send a model the whole warehouse. Give it a small JSON slice: this department, this as-of, these four cards, the top unit, the new names. If the key is missing, still print something a human can check.

Build

  1. Same snapshots. workforce.fake.json and ops-pulse.fake.json — invented Northwind Health Ops and Lanternfield Service Ops.
  2. Try-it box. Paste a note or pick a synthetic ticket. Client-side logic classifies the cut and writes a briefing. Unmatched notes stay unmatched — no invented number.
  3. Fallback first. The page is the contract: same note, same briefing. A hosted model would receive the same JSON slice. You still own the last mile when the model is wrong.

Result

A briefing you can try without a key. Live: demo/llm.html. This note is new work for a public evidence page. It is not a republish of a client notebook.
